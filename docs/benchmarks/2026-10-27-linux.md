# Benchmarks — 2026-10-27, Ubuntu 26.04 (GitHub Actions runner)

`xvfb-run python3 tools/bench.py 5` in the [`bench` workflow](../../.github/workflows/bench.yml):
median of 5 runs per browser and page. Raw numbers are in [`latest-linux.json`](latest-linux.json).
Same pages as on [macOS](2026-10-25-macos.md) and [Windows](2026-10-26-windows.md).

**Machine:** GitHub's `ubuntu-latest` runner, a VM: 4 vCPUs (AMD EPYC 7763), 16 GB RAM,
**no GPU**, X server is Xvfb (software rendering for everyone). canbec at `e9d3c0a` on WebKitGTK
2.52.6; Google Chrome 155.0.8059; Firefox 157.0. Not a real desktop: read the caveats.

| Browser | Size on disk | Time to window | PSS, probe | PSS, Wikipedia | RSS, Wikipedia | Processes |
|---|--:|--:|--:|--:|--:|--:|
| **canbec 0.1** (wry / WebKitGTK, full EasyList on) | **6.5 MB**¹ | 25.1 s² | 719 MB | 637 MB | **1,019 MB** | **4** |
| Google Chrome | 441 MB | **0.38–0.44 s** | **534 MB** | **544 MB** | 1,667 MB | 14 |
| Firefox | 304 MB | 1.3–1.4 s | 776 MB | 767 MB | 1,808 MB | 16 |

**In short:** on this GPU-less VM canbec uses **about 17% more memory than Chrome** (PSS, the fair
number) and **about 17% less than Firefox**. The macOS gap (2.7× less than Safari) doesn't show up:
WebKitGTK renders in software here and keeps more in its web process. RSS (shared pages counted in
every process) looks better for canbec only because it has 4 processes instead of 14–16.

¹ Plus WebKitGTK (`libwebkit2gtk-4.1`), which the distro installs and shares with other apps.

² **Not real.** 25.1 s is D-Bus's default call timeout: the runner has no desktop session bus, and
GTK most likely waits for it (accessibility bus) before showing the window. Chrome and Firefox don't
wait. On a normal desktop there is a session bus. The workflow now runs under `dbus-run-session`
to measure it properly; this table gets updated from that run.

## How it's measured

- **Time to window:** from launch until any process in the launched tree owns a visible X11 window
  (`xdotool search --onlyvisible --pid`, polled). Not first paint.
- **Memory:** summed over the launched process and all of its children, 15 s after the window
  appeared. **PSS** (from `/proc/<pid>/smaps_rollup`) splits shared pages fairly between processes;
  **RSS** counts them again in every process.
- Throwaway profiles: `CANBEC_CONFIG_DIR`, Chrome `--user-data-dir`, Firefox `-profile`. canbec gets
  the full EasyList, like on the other OSes.

## Caveats (read before quoting)

- A shared cloud VM without a GPU is not a laptop. Numbers on a real Linux desktop (GPU, compositor,
  session bus) will differ, likely in canbec's favour on time to window and possibly memory.
- Chrome printed `Sandbox: CanCreateUserNamespace() ... EPERM` (the runner restricts user
  namespaces), so it may have run with a weaker sandbox than on a desktop.
